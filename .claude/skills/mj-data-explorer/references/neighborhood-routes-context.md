# Neighborhood Routes Context

How and when to use the pre-computed neighborhood-route data files.

## Files

| File | Location | Purpose |
|------|----------|---------|
| `neighborhood_routes.json` | `tools/neighborhood-routes/neighborhood_routes.json` | Lean mapping — read this for all neighborhood ↔ route Q&A |
| `neighborhood_routes_full.json` | `tools/neighborhood-routes/neighborhood_routes_full.json` | Full demographic dump — consult **only** per-`objectId` on explicit analyst request |

## Lean file structure

```jsonc
{
  "generatedAt": "2026-06-14T...",
  "sourceGeoJson": "Official_Neighborhoods_with_Current_Demographic_Data_(2024).geojson",
  "neighborhoods": [   // flat array, sorted by name ascending
    {
      "objectId": 13,  // int, join key into the full file
      "name": "Ridgewood Heights",
      "npu": "C",
      "sqMiles": 0.21,
      "population": 2191,                  // int or null
      "medianHouseholdIncome": 87000,      // int or null
      "transitCommutePercent": 9.1,        // 1 dp or null
      "carAlonePercent": 30.2,             // 1 dp or null
      "workFromHomePercent": 58.7,         // 1 dp or null
      "routes": [
        { "routeId": "26922", "routeShortName": "39" }
      ]   // [] when none
    }
  ]
}
```

## When to read the lean file

Read `neighborhood_routes.json` to answer:

- "Which routes serve neighborhood X?" → find entry by `name`, return `routes[]`
- "Which neighborhoods does route Y pass through?" → scan all entries, filter where `routes[].routeShortName == Y`
- "Which neighborhoods have the highest transit-commute share?" → sort by `transitCommutePercent` descending
- "Does route 39 pass through downtown neighborhoods?" → scan, collect names where route 39 appears in `routes`
- Any demographic ranking or comparison across multiple neighborhoods

Always read the file fresh from disk — do not rely on cached content from a prior turn.

## When to read the full file

Read `neighborhood_routes_full.json` **only** when the user explicitly asks for detailed demographics on **one specific neighborhood** by name or objectId. Never load the full file speculatively or for multi-neighborhood comparisons (it is large and not LLM-context-friendly).

### Full file lookup

```
full["neighborhoods"][str(lean_objectId)]
```

The key is `str(objectId)` — e.g., `"13"`. The value contains all verbatim GeoJSON properties (~130 fields): race/ethnicity, housing, home value, education, age, all `commute__*` fields at full precision, etc.

## Reverse index pattern

The lean file stores routes on each neighborhood; the reverse (route → neighborhoods) is not pre-computed. To answer "which neighborhoods does route 39 serve?", scan all lean entries and collect those where any route has `routeShortName == "39"`.

## Source of truth

These files are committed artifacts generated by `tools/neighborhood-routes/generate.py` against the live MJ API and the City-of-Atlanta GeoJSON. They are regenerated manually when GTFS shapes or the GeoJSON source change. Do not re-run the script during a skill session — read the committed files as-is.
