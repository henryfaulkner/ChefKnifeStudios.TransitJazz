# Delivery Timeline: Neighborhood Focus Mode

**Feature**: `011-neighborhood-focus-mode` | **Created**: 2026-05-29 | **Spec**: [spec.md](spec.md)

A coordinated, dated plan spanning code development, content production, skill
usage, and testing. This is a *tracking* document — adjust the dates to your
real availability. It assumes today is **Thu 2026-05-29**, planned in calendar
days (focused evening/weekend blocks), with realistic slack.

The central idea: **content production (tones + blurbs) runs in parallel with
code development** because both write to a data file whose *shape* is locked
early. Freezing that schema is the gate that unlocks the parallelism — and is
where most schedule risk and most savings live.

### Track B — Content (you + the skills), can start 6/1

| Days | Work | Skill |
|------|------|-------|
| 6/1 | Hand-author ~10–15 neighborhood **polygons** (geojson.io or similar), names only | manual |
| 6/2–6/4 | Assign `featuredRoutes` + voice table per neighborhood | **`select-neighborhood-tones`** |
| 6/5–6/8 | Write per-neighborhood prose (must follow tones) | **`create-neighborhood-blurb`** |

**Ordering rules:**

- Blurbs describe the *assigned voices verbatim*, so tones must precede blurbs
  **per neighborhood** — but pipeline it neighborhood-by-neighborhood; you don't
  need all tones done before starting any blurb.
- The voices authored in Track B (6/3) feed the voice builders in Track A (6/3).
  Keep them in sync, or do Track A's voice builders *after* the voice table
  settles.

**De-risking move — do this first:** on **6/1**, complete **one** neighborhood
(Midtown) end-to-end — polygon, tones, blurb — as a vertical slice. It validates
the schema, both skills, and the data shape *before* mass-producing 14 more.
Cheap insurance against authoring everything against a wrong schema.

## Where it's most likely to slip

1. **Schema not truly frozen on 5/30** → both skills and all authored data
   churn. Treat the freeze as hard.
2. **Voice table drift** between Track A's builders and Track B's authoring → do
   the Midtown slice first so the voice set settles early.
3. **Boundary jitter** (FR-014 / SC-006) is the subtlest bug → give it the 6/11
   polish day; don't discover it on 6/12.
4. **Testing needs live buses** → don't schedule 6/12–6/13 verification for a
   time MARTA isn't running.
