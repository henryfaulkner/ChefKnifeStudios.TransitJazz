# Seattle verification design

This is a future test and acceptance plan, not a record of executed checks. Use the repository's xUnit projects and the smallest layer that proves each observable behavior. The [source contract](contracts/seattle-source-and-identity-v1.md), [visitor/release contract](contracts/seattle-visitor-and-release-v1.md), and [validation record](validation.md) define the expected behavior and where measured results belong. The 2026-10-18 compatibility samples are research evidence only.

## Deterministic fixture boundaries

- Use small, synthetic GTFS-RT protobuf messages with source label, descriptor, route, position and vehicle timestamp; no saved live feed or raw production vehicle ID. Fix receipt UTC with `TimeProvider` and test both equality and just-outside freshness/overlap bounds. Build each test's configuration and HTTP handler anew.
- Capture outgoing requests with a per-test `HttpMessageHandler` and a sentinel key supplied through an injected/test-only source access seam. Assert the ST request has exactly one `key` parameter, while KCM and both static requests have none. Capture the request before simulating non-2xx, malformed content, redirect and exception paths. A redirect fixture must prove the credential cannot be forwarded to a different host. Capture logs and public response text to assert the sentinel and full authenticated URI never appear. Avoid mutating process environment variables in parallel xUnit tests; a small source-specific key provider seam is preferable to mutable ambient state. No network call belongs in these tests.
- Build minimal in-memory direct GTFS ZIPs (`routes.txt`, `trips.txt`, `shapes.txt`) for aliases and conflicts. Keep a third synthetic ZIP with `512` geometry solely to prove the exclusion is explicit and persists if geometry appears in a future direct ZIP. Do not load the retired regional URL in any fixture.
- Feed the selected Seattle result into an existing Worker fixture with a recording publisher and route-hour sink only for the one-contribution invariant. Verify published vehicle/crossing and history outcomes, not private matching helper calls. Use one fixed clock and no sleeps; assert unordered collections as sets unless order is part of the contract.

The matrix names candidate files, not mandatory new suites. If an existing seam proves a behavior, extend it. Do not add database migrations, a new test framework, broad end-to-end test harness, or one test per private helper. A single test should fail for a clear behavioral reason; share compact fixture builders only where they make expected inputs visible.
