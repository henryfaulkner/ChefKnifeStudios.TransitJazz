## Summary

Capture route activity, movement, processing, detected/published crossings, and suppression during the existing worker pass. Resolve canonical city-scoped routes from the live catalog snapshot, accumulate bounded UTC-hour state, and retain each immutable city/hour cohort atomically in one new table.

Reuse `HistoricalStatistics.Enabled`, `DryRun`, and resolved `Cities`. Limits live under `HistoricalStatistics:RouteHours`. A dedicated asynchronous writer preserves live cadence. Complete evidence requires stable catalog content, eligible cycles, and healthy boundaries/gaps; there are no durable route minutes. Deliver internal coverage, hourly, weighted-period, and local-hour SQL recipes. Preserve existing city/category and live-output contracts.

## Design Details

### Canonical identity and cycle capture

Build canonical metadata/aliases alongside route indexes in one `RouteCatalogSnapshot`. Group by `RouteShapeProperties.JoinKey`, not raw feed IDs or `_routeIndex.Keys`. Fingerprint actual final concatenated ordered geometry using the versioned length-prefixed UTF-8/ordinal encoding in [research.md](research.md). Preserve category's numeric-generation behavior; route capture compares content and resets only affected baselines. Reject blank, over-512-UTF-8-byte, or ambiguous case-colliding auxiliary geometry identities without altering live routing. A refresh during processing cannot provide Complete mixed-catalog evidence.

Begin a cycle against the same snapshot as live processing. Record valid positioned joined activity once in feed order; movement after snap with source freshness; processed/stale observations beside existing count branches; suppression at its assigned reason; detected records from actual prepared crossings; and publication only after publisher returns true. Keep counters independently from recyclable lists.

Each hook, begin/commit/refresh/prune/sweep/flush, must catch instrumentation-only failures and flag capture loss without entering live per-entity/reconciliation catches. Successful publication stays known even if subsequent instrumentation fails. Complete once at the outer city boundary with one UTC completion timestamp, source/processing/publication outcomes, nonempty ready cohort, and final content recheck. Healthy empty cycles provide all-route zero samples. Partial work retains diagnostic counters/known publications. Movement mirrors existing six-decimal away-from-zero rounding, monotonic watermarks, clear/reseed rules, and 20-minute pruning; repeated synthetic source timestamps remain rejected.

### Hour coverage and lifecycle

Retain at most current and boundary-pending observed hours/city. Healthy predecessor/successor timing brackets both boundaries; the successor's counts belong only to its new hour. Require stable enabled capture, all eligible cycles/known publication, acceptable gaps and intact populations for Complete. Persist no covered-minute count. Startup/shutdown, catalog changes, failures, clock regression or caps are incomplete; no eligible samples is NoData; lost envelopes are Missing.

Run an independent `PeriodicTimer(TimeProvider)` sweep <=15 seconds. Share one short state lock with commits: freeze under it, then validate/enqueue/report outside it. No network, logging, retention, or admission I/O under the lock. Track sealed progress so late/regressed completion never reopens a swept hour. Do not fill/replay all missed windows. Worker/lifecycle flushes are idempotent. Register writer before lifecycle and Worker so reverse stop flushes capture before admission closes/drain; explicitly verify sequential service stop ordering.

Catalog changes preserve the union of old/new routes and first metadata per entry, flag all city/hour rows, reset affected movement, and invent no full-hour zeros. Identity limits are enforced in cycle recording as well as hourly merge; population loss sets denominator null. Stop extra capture for the lost hour; if an honest route union cannot fit, drop the entire envelope and report. Resume only in the next within-limit hour with reseeded movement as needed.

### Atomic retention, retry and host modes

Use [data-model.md](data-model.md)'s whole-envelope protocol: fresh read-committed transaction, stable namespaced city/hour advisory lock in a separate command, then cohort lookup. Insert all sorted rows in <=128-row commands inside one transaction. Exact existing cohort/payload yields Unchanged; any difference quarantines every old row without inserts/overwrites/fragments. Equality includes run/definition/cadence/metadata/counters/coverage and excludes only generated persistence time and monotone conflict.

The singleton writer/sink has bounded Channels `FullMode.Wait`, only synchronous producer `TryWrite`, one reader, and no synchronous continuations. Admission is memory only. A linked attempt timeout covers connection, advisory lock, all commands and commit; transaction-local statement/lock timeouts prevent pool leakage. Retry recognized transient failures with the exact envelope up to three attempts and one/two-second delays. Acknowledgement loss resolves by identical retry. Log bounded outcomes and explicit whole-envelope loss.

Project existing host-resolved history selection into Worker runtime options. Disabled mode registers a no-op sink and skips route capture/sweep/writer. Dry run validates/reports without any route store call/write; preserve the host's current enabled-history DB-configuration requirement even for dry run. Persistence validates a real sink and registers store/writer before capture. Category settings stay independent. Standalone Worker rejects enabled route persistence without a real sink; intentional dry-run support must explicitly provide its sink.

### Queries, schema and rollout

The [contract](contracts/observed-route-hour-statistics-v1.md) and [SQL](contracts/route-hour-insights.sql) cover explicit expected-hour grids, historical routes, coverage/diagnostics, weighted periods, and local hours. Complete nonconflicting fully contained hours alone contribute definitive metrics; versions/cadence are separate. Keep requested/contributing counts, earliest retention, bounds, offsets, units, fingerprints and denominators visible. No average-of-averages, proration, or period/city uniqueness claims. All-route discovery cannot reconstruct an entirely missing historical cohort.

Add one schema-only migration to the existing Data bundle. Preserve old schema/migrations/secret. Add a narrow new-migration workflow guard; do not weaken earlier category guards that forbid route data in that older migration. Keep committed history defaults disabled and dry run true. Reuse deployment parameters/city scope; resource tunables may extend Bicep only without a new flag and require regenerating main.json. Apply schema before code through the existing operator process. No new one-city pilot gate, deletion job, or backfill.

## Validation Strategy

- Worker fixtures: canonical aliases/grouped shapes/city/case/collisions, content-identical/change/in-flight refresh, positions, feed-order duplicates, stationary/reverse/2,000-meter movement, timestamps/transfers, processing branches, suppression, actual/failed publication, healthy empties/mixed failures, and throwing capture hooks preserving live outcomes.
- Clock fixtures: UTC boundaries, all gaps/deadlines, startup/shutdown/idempotent flush, sweep during flight, long pause, sealed hour, catalog unions, caps and unavailable distinct denominators.
- Host/writer fixtures: existing controls/resolved scope/category independence, no disabled work/no dry-run writes, sink/DB validation, configuration bounds, immediate full admission rejection, finite retries/timeouts/drain, safe reports and stop order.
- Disposable PostgreSQL: fourth entity and checks, whole-envelope later-command rollback, concurrent identical/different cohorts/runs/versions, lock timeout, acknowledgement loss, sticky whole-hour quarantine, no fragment merge, and snapshot-consistent missing/partial/weighted/DST SQL. Never delete an operator database.
- Run relevant old worker/city/category regression tests, build server and existing migration bundle/image, and inspect the new schema-only migration. Disclose skipped disposable checks.
- Measure <=5% p95 overhead, >=99% Complete eligible route-hours over 24 healthy hours after startup fragments, zero loss/conflicts, resource growth/cadence, and analyst comprehension (at least 4/5). These checks are not executed by this planning workflow.
