# Contract: PR Delivery Boundary

This is the safety-critical contract of the feature (User Story 3 / FR-013–FR-015 /
FR-017). It exists as its own contract file, separate from the stage contract, because it
is the one part of this feature where a mistake has consequences beyond a bad report — a
violation here could touch shared repo state.

## Invariants (never conditional, never relaxed by any branch behavior elsewhere)

1. **Exactly one file changes**: `docs/city-compat/{slug}.md`. Nothing else — no skill
   files, no other docs, no application code, no `candidates.md` edit (the candidates file
   is a static seed list; dedup is computed live against existing reports, so a run never
   needs to write to it).
2. **`main` is never a direct commit target.** Every commit this feature ever makes lands
   on a `compat/{slug}` branch, full stop — including every failure path.
3. **The skill never merges its own PR.** Opening the PR is the terminal action of a
   successful run; merging is exclusively a human action.
4. **No onboarding side effects.** This feature MUST NOT invoke `add-transit-city`, edit
   `CityNames.cs`, either `appsettings.json`'s `Cities:` array, `CityFab.razor`, the
   `_cityCenter` map origin dictionary, or any `.resx` overlay content — even when the
   verdict is a clean COMPATIBLE. Onboarding remains separate and human-triggered
   (FR-015).

## Preconditions before the STAGE 6 git sequence begins

- `git status` at the start of STAGE 6 shows only the one new report file as untracked/
  modified. If anything else appears, STOP — do not proceed with `git add`; this indicates
  either a bug in an earlier stage or unrelated in-progress work in the working tree that
  must not be swept into this run's commit.
- The working directory is confirmed to be the repo root (re-asserted from STAGE 0).

## The exact command sequence (no deviation)

```powershell
git checkout -b compat/{slug}
git add docs/city-compat/{slug}.md
git commit -m "compat: evaluate {AUTHORITY} ({City})"
git push -u origin compat/{slug}
gh pr create --title "Compat report: {AUTHORITY} ({City}) — {verdict}" --body "..."
```

The PR body MUST include, verbatim or near-verbatim:
> Auto-generated by the discover-transit-city scheduled routine; review before merging.
> This does **not** onboard the city.

## Degraded-path handling (FR-017)

| Failure point | Required behavior |
|---|---|
| `git push` fails (network/auth) | Branch + commit remain local. End the run reporting: the branch name, that the commit succeeded, and that push failed with `<reason>`. Do NOT retry indefinitely, do NOT fall back to `main`. |
| `gh pr create` fails (auth/network/API) | Same as above, but note the push succeeded and only PR creation failed — a human can open the PR manually from the pushed branch. |
| Both succeed | Report the PR URL as the run's terminal output. |

## Why this is a separate contract from the stage contract

The six-stage contract (`skill-stage-contract.md`) describes what each stage *produces*.
This contract describes the **one thing that must remain true no matter which stage path
was taken to get here** — a COMPATIBLE run, a PARTIAL run, and a BLOCKED run all converge
on identical STAGE 6 behavior. Separating it makes the invariant easy to re-verify in
isolation (e.g. during the manual dry-run in the build checklist) without re-reading the
whole orchestration.

## Verification checklist (used during the manual dry-run, before scheduling)

- [ ] `git status` immediately after STAGE 5 shows exactly one new file.
- [ ] The new branch name matches `compat/{slug}` exactly.
- [ ] The commit contains only `docs/city-compat/{slug}.md` (`git show --stat HEAD`).
- [ ] `main` has zero new commits after the run (`git log main..compat/{slug}` shows the
      one commit; `git log origin/main` is unchanged).
- [ ] The opened PR targets `main`, not any other branch.
- [ ] The PR body contains the required "does not onboard the city" sentence.
- [ ] No file outside `docs/city-compat/` was touched at any point in the run.
