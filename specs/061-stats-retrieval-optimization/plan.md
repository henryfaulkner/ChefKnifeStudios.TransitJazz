# Implementation Plan: StatsOverlay Retrieval Optimization

**Feature directory**: `specs/061-stats-retrieval-optimization` | **Date**: 2026-10-30 | **Spec**: [spec.md](spec.md)  
**Branch**: Existing checkout retained; no branch creation or switching.  
**Input**: Entire [originating design](../../docs/STATS_OVERLAY_RETRIEVAL_OPTIMIZATION_DESIGN_DOCUMENT.md). Artifacts only; no implementation, measurement, deployment, or enablement has occurred.

## Summary

Extend the existing singleton StatsOverlayService with exact selected-route coalescing, bounded filtered retention, and server-owned fixed UTC refresh windows. Add optional scheduling metadata to the existing response. Move browser retrieval into one app-owned StatsSnapshotStore, retaining current city, All, and the latest filtered selection. The overlay reads matching evidence synchronously and preserves presentation during refresh; preparation runs only when enabled and visible. Preserve the existing SQL, reporting semantics, endpoint safeguards, map/audio startup, and independent units preference.

No measurable map/first-audio regression against recorded variability. Measurements remain future release gates.

**Scale/Scope**: <=32 cities plus All; server 33 entries/64 MiB, filtered subset eight/16 MiB inside totals; app three snapshots/32 MiB. Hourly default with 2-minute grace; integer intervals 1–60 dividing 60. Evaluate 500 visible apps and synchronized bursts; ~1,000 baseline responses/hour is conditional arithmetic, not a benchmark.

## Design Details

### Server scheduling and identity

Add only RefreshIntervalMinutes=60 to configuration; retire CacheSeconds from active server policy/config/tests. Validate the divisor interval at startup. Filtered retention uses fixed internal caps of eight entries/16 MiB, clamped to the existing configured total limits. Use TimeProvider and Unix epoch UTC origin plus existing grace. Effective expiry is the next fixed boundary or earliest future root city-window day end. Resolve reporting with real request time using unchanged StatsOverlayPolicy.Resolve, preserving completed hours and previous-day semantics.

Canonical structured serialization includes scope/city, distinct ordinal-sorted route keys, refresh window/interval, cutoff, per-city date/zone/cadence, versions, configured membership, grace and reported-vehicle settings/fingerprints. Exact material, or a digest plus equality verification, keys both retained and in-flight work. Selection slots include exact keys. Entries carry UTC expiry, monotonic deadline, generation and access sequence. Expire on either clock basis; observed server-clock rollback flushes retained entries. Later rollback cannot resurrect evidence.

### Shared fills and admission

Publish a matching promise under a short lock, acquire readSlots.Wait(0), then start work outside the lock so immediate completion cannot race registration. Exact duplicates join for all selections. Shared CTS links only five-second deadline and host shutdown; caller cancellation stops its WaitAsync. Finally remove only the matching promise and release resources on every outcome. Preserve deadline through query, projection and bounded size validation. No SQL changes.

Never retain a fill finishing at/after its original boundary or replace a later generation/window. A crossing response may reach a waiter with original expired metadata and permit one admitted follow-up. Conservative estimate is existing serialized UTF-8 bytes*8+4096 plus canonical key/entry overhead; serialize once for validation/admission. Expired first; filtered LRU can evict filtered only; baseline evicts filtered first then oldest baseline. Enforce subset and total counts/bytes independently. Nonfitting valid evidence returns uncached. All valid 200 states are eligible; failures are not. All remains its own consistent read.

### Client ownership and scheduling

Register one StatsSnapshotStore per WASM app. Start idempotently from App.OnAfterRenderAsync(firstRender), subscribe navigation/shared visibility then query initial visibility; observe owned tasks without awaiting warmup. Keep map AddVisibilityChangeListenerAsync ownership. App teardown cancels/awaits store and unsubscribes. Existing StatsOverlay gate controls all statistics work, including startup preparation. The refresh interval is the only new configuration setting. stats_disabled suppresses automatic attempts until reevaluation/reload.

Store owns exact-selection state, per-slot generations/errors/backoff, one HTTP request and one cancellable earliest-wakeup delay. Keep city, All and latest filtered snapshots within 32 MiB, in that retention priority. Navigation invalidates old city/filtered work, retains All and prepares new city. Enabled statistics refresh visible baselines while the dialog is closed. Filtered work is automatic only when displayed. Keep 200 ms debounce/latest desire; duplicates join. Displayed work starts first, then alternate due city/All with at most one interactive turn before a due baseline, preventing starvation.

Each accepted window samples one independent 0–5 second positive jitter; never before returned boundary. Include day/stale/expiry wakeups under backoff. Hidden cancels browser waiting transport and pauses network scheduling, retaining data; resume evaluates elapsed age and refreshes needed selections once. One request admission includes open/retry/resume. Endpoint-wide 429 cooldown cannot be bypassed; other retry state stays per slot. Retry starts at 60 seconds, doubles to five minutes and honors longer Retry-After. HTTP success resets transport backoff; invalid successful evidence leaves invalid_response and stale prior evidence.

Validate required structure/versions/exact selection/times before atomic publication. Reject superseded navigation/selection generations and older GeneratedAtUtc across replicas. Identical evidence updates contact only, retaining deadlines and avoiding chart rebuild. Newer generation replaces evidence only with valid schedule/order. Store acceptance is independent of dialog generation/closure.

Clock policy: allow at most 30 seconds of future generation skew; validate effective boundary <=generation+interval and coherent with window/root day metadata. Convert UTC deadlines once at receipt to TimeProvider timestamps, clamping remaining freshness to [0, interval]. Never re-anchor unchanged evidence. Stale at known failure immediately or original boundary+30 seconds; hard expiry boundary+2*interval. Day end immediately marks explicitly dated daily evidence historical/stale; otherwise withhold daily presentation. Larger skew/invalid order is invalid_response. All absent schedule fields uses legacy minute scheduling and hard expiry GeneratedAtUtc+60 seconds with no extended closed-dialog fallback; partial fields invalid. Contract details follow.

### Overlay, diagnostics and rollout

Overlay reads matching state before requesting missing/due work. Remove direct transport and timer there. Preserve charts/tables/focus during same-selection refresh; missing exact selection honestly loads/unavailable. Project only while open and DTO or presentation inputs change. Close unsubscribes presentation while retaining store state; reopen defaults city/unfiltered. Theme/units never affect retrieval identity. Use original update time, independent coverage/freshness, polite failure/recovery announcements and resx; no per-tick announcements/main-app rerenders.

Extend existing server meter with bounded scope/selection-kind/results, occupancy/estimated bytes and fill duration. Client Stats diagnostics do not currently exist: extend ILogger plus optional existing Umami helper for aggregate preparation/open/loader/failure/timing events. No raw routes, keys, hashes, visitor labels or new platform. Instrumentation failure cannot affect requests. Browser traces measure drawing, actual heap, serialization and startup separately.

Capture baseline before comparisons. Roll out schedule-aware serving/filtered retention, then store-backed on-open overlay, then preparation. Measure legacy minute-client overlap. Roll back preparation independently; set filtered entries to zero independently; Stats gate stops all work. Keep endpoint/SQL unchanged. No production changes are authorized here.

### Deterministic time, doubles, ownership and cleanup

- Extend the existing hand-written clock approach with a small composable manual TimeProvider per test project: proposed `S/StatsOverlayTestTimeProvider.cs` and `C/StatsSnapshotTestTimeProvider.cs`. It must independently control UTC and monotonic timestamp, implement controllable timers used by `Task.Delay`/deadline cancellation, and let tests advance to exact instants and drain signaled work. The current cache test's UTC-only MutableTimeProvider is insufficient for monotonic expiry or deadline tests. Verify timer cancellation/disposal with focused helper tests in its consuming suite; use one clock for all paths of a SUT, not a real deadline beside a fake schedule.
- Inject a simple deterministic jitter sampler/delay seam into the client store. Supply fixed sequences including 0, an interior value and 5 seconds; record samples to assert one sample per selection/window and independent selection samples. Assert requested deadlines/observable calls, never a statistical distribution. Before/at/after means one tick before, exact deadline and one tick after; route debounce likewise tests 199 ms, 200 ms and 201 ms.
- Reuse hand-written counting/blocking `IStatsOverlayQuery` and HTTP-handler spies with per-request started, released, canceled and completed TaskCompletionSource gates (`RunContinuationsAsynchronously`). Release responses in an explicitly chosen order. Cover immediate return, synchronous throw and asynchronous failure, not only blocking operations. Use `Interlocked` for active/call counters. Cancellation spies expose tokens so tests distinguish caller, hide/navigation/stop, deadline and host cancellation.
- Keep real policies/selection/serialization inside the SUT; double only external query, transport, visibility, navigation events and optional diagnostics delivery. A small event spy records subscriptions, initial visibility ordering, StateChanged selection/count and disposal. Stub diagnostics to throw to prove retrieval still succeeds. Avoid strict mocks of private sequencing; query count, peak active requests, returned evidence, boundary/error state and public notifications are the meaningful contracts.
- Give each test fresh service/options/store/clock/handlers and request data; do not mutate global flags, production configuration or process environment in low layers. Await started/completed signals rather than fixed sleeps, Task.Yield loops or elapsed performance assertions. Bounded real WaitAsync watchdogs only detect a hung test, with a documented CI-appropriate bound; they do not drive expected behavior and must not become retries.
- Dispose/cancel and await all outstanding fill/store/timer tasks in `finally`/`await using`, including failing assertions. Assert no requests/notifications after stop and every slot can be reused after completion/cancellation/failure. Unsubscribe event spies, dispose HTTP/TestHost objects and MeterListener. Static-meter assertions must filter finite tags/instrument under test and use thread-safe capture; if exact global counts cannot be isolated, put that suite in one nonparallel xUnit collection instead of disabling unrelated test parallelism.
- PostgreSQL checks keep `RouteHourPostgresFact`, `RouteHourStatisticsDatabaseFixture` and `ROUTE_HOUR_HISTORY_DISPOSABLE_CONNECTION`: explicitly provision a database whose name contains `disposable`; fixture creates a unique database, migrates/seeds and drops it in async cleanup. Keep database tests opt-in with missing configuration reported as skipped, never passed. No shared production data or EF in-memory substitute for PostgreSQL semantics.
