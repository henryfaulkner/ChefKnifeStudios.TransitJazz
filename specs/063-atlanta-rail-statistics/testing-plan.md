## Fixture mechanics and reliability

T04 uses fresh fixed Atlanta bus/rail shapes within the existing snapped geometry checks, fixed run ID and explicit `marta-bus`/`marta-rail` inventory frozen for each hour. Use `2026-11-07T12:00:00Z` as core hour, 10-second polls and source predecessor/successor support; assert actual in-hour sample count from explicit poll schedule. Positions move less than the existing jump threshold with increasing event timestamps; independently sum known snapped segment distances rounded at persistence precision. Do not force 120km via one enormous jump. Arithmetic fixtures use exact120 independently of the movement journey. Include rail fixtures with an explicitly supported event-time contract; unverified live timezone remains unrun.

Reuse controlled clocks/sink/publisher and source/HTTP stubs by composition; extend existing local helpers only where needed. Actual Worker tests inspected call ProcessSpatialReconciliationAsync and manually mark activity eligible: those tests alone would miss the original combined-fetch regression. T04/focused orchestration regression must pass actual CityFetchResult outcomes to capture through production cycle orchestration (a minimal internal seam if necessary), not reimplement eligibility in fixture code. Keep the production timer loop outside tests and do not add polls. No new universal harness/builder is justified beyond the small journey fixture.

PostgreSQL tests use existing `RouteHourPostgresFact` and `RouteHourStatisticsDatabaseFixture.CreateAsync()` from A. An operator-provisioned `ROUTE_HOUR_HISTORY_DISPOSABLE_CONNECTION` must name a database containing `disposable`; fixture uses create-database permission, migrates a unique child and drops only that child on disposal. Never print/assign a real connection in command text or silently fall back to a serving DB. Upgrade test needs a small fixture option to stop at pre-feature migration before seeding/applying; keep the same guard/unique child/cleanup path. Use fresh fixture per independent test; parallel tests do not share mutable rows/catalog/options/clocks. Per-test explicit migration and transaction state are real EF/Npgsql, not SQLite/in-memory substitutes.

Concurrency uses started/release TaskCompletionSource signals with RunContinuationsAsynchronously and cancellation in finally; deterministic clock controls expiry/deadlines/monotonic timers, no sleep or retry-to-green. Existing real-time WaitAsync guards can bound hangs without asserting exact runtime duration. Set cleanup guards generously enough for local CI; only controlled performance work measures timing. SQL/query deadline/cancellation tests assert outcome and no leaked work, not stopwatch microbenchmarks. No mutation of culture/environment/shared DefaultRequestHeaders without local scope/restoration; prefer explicit localizer/culture/timezone options. Use ordinal/order-independent assertions according to contract; known canonical arrays assert exact ordinal order.
