# Testing Plan: Useful Failure Notifications

This is the pre-task testing/TDD enrichment required by FR-022. It refines [plan.md](plan.md), the [specification](spec.md), both [policy](contracts/notification-policy-v1.md) and [outcome](contracts/capability-outcomes-v1.md) contracts, and the [governing design](../../docs/TOAST_NOTIFICATIONS_DESIGN_PLAN.md). This document plans evidence; it does not claim tests or browser checks have run. No application/test implementation or tasks are generated here.

## Existing conventions and layer choices

Use `src/Client/ChefKnifeStudios.TransitJazz.Client.Shared.Tests` for pure Core/Shared behavior. Its desktop `net10.0` host references Shared (which references Core), uses existing xUnit 2 `[Fact]`/`[Theory]`, PascalCase behavior names, and hand-written local spies/stubs. Keep Arrange/Act/Assert visible, fresh state per test and one behavior per test. Assertions may jointly prove that behavior (for example truthful unavailable state and zero duplicate presentation).

Grounding references are `AttentionGateTests.cs` (held operations/single in-flight reconciliation), `StatsOverlaySessionTests.cs` (generation leases and event-based cancellation), `StatsOverlayRetryTests.cs` (explicit boundary instants), `StatsTransportTests.cs` (in-memory HttpMessageHandler/content disposal), and `StatsAccessibleEvidenceTests.cs`/`StatsResourcesTests.cs` (model/resource assertions). Reuse patterns, not their incidental wall-clock timeout/cancellation choices. Existing server fixed TimeProvider examples override UTC only; they cannot drive the monotonic timers needed here without extending the clock seam.

## Deterministic time, ordering and isolation

- Inject a single `TimeProvider` for all application policy/reading deadlines and use `GetTimestamp`/elapsed time. Add a small test-local controllable provider only as needed: fixed UTC for diagnostics, independently advanced monotonic timestamps, controlled `CreateTimer`/`ITimer` change/disposal. A UTC-only fake cannot prove deadline scheduling. Keep vendor DateTime.Now timers outside policy tests by RequireInteraction and disabled transitions. No new time package or general scheduler framework.
- Exercise the production scheduled wake-up as well as explicit evaluation: at most one next active coordinator deadline, wake then evaluate current state, cancel on dispose, and no rescheduling tight loop after presentation failure. Use a bounded drain/completion signal for due callbacks; do not `Task.Delay` to let work settle. Test callbacks arriving after cancel/dispose because cancellation cannot unsend an already queued callback.
- For 2s burst, 10s grace/spacing/conditional thresholds, 20s watchdog, 30s healthy re-arm and 8/12s reading, assert immediately before, exactly at and immediately after the boundary using clock ticks. Test minimum eligibility followed by burst separately: C3 becomes eligible at visible t=10, first presentation at t=12 after collection; a terminal escalation obeys >=10s since last successful presentation. Failed stop may bypass spacing, but still follows current eligibility/aggregation rules; do not invent a bypass of all policy.
- Example fixed burst: reports at t=0/0.4/1.2; no Add at 2s minus one tick, one at 2s, no shift to 3.2s. A new incident during spacing completes its own fixed burst then waits; recover it before spacing ends and assert no later replay. Test warning-to-error with spacing when the warning is still active and after it was dismissed.
- Continuous-visible reconnect/foreground grace resets on hide/pause; reading time pauses rather than resets on hidden/hover/focus (including overlapping pause reasons). Confirmed healthy time resets on failure/unknown/pause without health proof; t=29s suppressed, >=30s continuously healthy re-arms. UTC jumps forward/back must not change any of these outcomes. A5 uses unresolved time, not the M5 visible-batch span; follow the contract rather than sharing a guessed silence detector.
- Use per-test `TaskCompletionSource` with `RunContinuationsAsynchronously` and explicit entered/release/completed signals to hold start/join/HTTP parse/import/effect/save/presenter completions. Run old-then-new and new-then-old completion orders deliberately; no random races or test retries. Bounded `WaitAsync` is a hang guard only, with a documented diagnostic timeout, never a timing assertion. Cancel/release all gates in `finally` and await owned tasks on teardown.
- Same-instant reports and boundary recovery have no contractual arrival ordering. Define and test the serialized order explicitly: recovery before commit suppresses; a presentation already committed before recovery may be removed silently. Assert equal capability sets/severity for equivalent report permutations, avoiding incidental dictionary/HashSet order; any output order uses a stable capability order. Do not assert that races can never occur because a single-threaded fake hides them.
- Fresh coordinator, scope, settings snapshot, recorder, clock and fakes per test; no shared mutable singleton/culture/browser storage. Resource tests scope and restore culture. Isolated browser profile/state per scenario, reset storage/module fault setup between cases, detach listeners/references and clear test-owned injections. Fixed finite fixtures only; no production data, timing-sensitive feed silence or environment-variable changes in low layers.
