## Execution rules

- All paths below are exact repository-relative targets; new test/type names are proposed concrete homes, not a requirement to proliferate classes.
- RED means write/run the expected visitor behavior and record its intended assertion failure **before** the corresponding GREEN application change. Missing-API compilation failure alone is insufficient: make a minimal compiling seam, then observe the assertion fail. GREEN means implement the smallest passing behavior. REFACTOR means simplify only with that focused test still passing. Record test names, failing reason, commands/results and artifacts in `specs/061-enrich-failure-notifications/validation-evidence.md`.
- Every timed test uses monotonic timestamps and scheduled callbacks, checking one tick before/exactly at/one tick after 2/10/20/30-second and 8/12-second boundaries as applicable. Distinguish eligibility from the following two-second collection window. No wall-clock sleep, random race, live feed or production outage.
- Hold asynchronous work with test-local entered/release/completed signals, deliberately test both completion orders, release/cancel/await in cleanup, and reject queued callbacks after cancellation/disposal. Hang guards are diagnostic only. UTC jumps must not alter policy.
- `[P]` means files are disjoint and prerequisites already complete. Only explicitly listed sibling groups may run together; test execution that shares an evidence file is recorded serially. Shared production files remain sequential.
- Foundational phases deliver shared truthful facts, policy and the real adapter before story integration. Story phases add owner-to-policy behavior with independent visitor tests; foundation tests alone do not claim any story complete.
- Preserve unrelated dirty work. **Never commit, run commit-producing hooks, publish or deploy.** No new runtime/test framework, notification bus, server endpoint, global exception/request interceptor, guessed silence detector or blanket retry.
